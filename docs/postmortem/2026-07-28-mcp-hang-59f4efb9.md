## Part A — Hang incident

### Verdict

The ~11 hour “stop” was not a deliberate pause. A **phone MCP tool call stopped returning**, the **serial batch never wrote a finish marker**, and the **agent stayed on a long `AwaitShell`** with no heartbeat watchdog. Three layers failed open.

### Timeline

1. Serial batch 3 started ~12:13 local; last useful log ~12:20 (after `hunt_empty` → `prep` → `cooldown 3s`).
2. No further `REPORT_JSON` / finish fields → stuck inside the next phone MCP step (`get_source` / `debug_source` / verify).
3. Agent waited on shell completion; wall clock ~10.9h until the user asked for status.

### Failure stack

| Layer | Failure | Mitigation |
|-------|---------|------------|
| **Phone MCP** | In-flight tool call did not complete / half-open TCP | App: health, defer restart while busy, stale release, reset tool (`bfdd4a0d0`) |
| **PC channel lock** | Windows `pid_alive` always true → 6h TTL | legadoSkill `channel_pid` + shorter stale |
| **PC serial** | In-process oneshot blocked whole batch | subprocess + `--url-timeout-s` + heartbeat |
| **Agent ops** | Long `AwaitShell` on whole batch | discipline §19–20 + SKILL traps |

### Root-cause hypotheses (ranked)

1. **Most likely:** long phone tool call + **engine restart on Wi‑Fi churn** or non-returning streamable-HTTP session.
2. **Likely:** hung `debug_source` / verify where cancellation did not surface to HTTP.
3. **Amplifier:** Windows zombie lock + agent AwaitShell.

### App hang mitigations shipped (`bfdd4a0d0`)

1. `GET /mcp/health` — `ok` / `busy` / `stale` / last tool timestamps (token required).
2. Defer `upMcpServer()` while debug/check busy (network **and** start/restart); apply when idle.
3. Watchdog ~3 min: restore service + force-release stale debug/check; unlock `debugMutex`.
4. `debug_source` default **90s** (align PC client); CIO `connectionIdleTimeoutSeconds=180`.
5. Tool `reset_mcp_channel`; check snapshot `lastProgressAt`.
6. Autorestart / NSD / lifecycle / task-removed keep-alive (same commit).

Review follow-up in that commit: do not mark check idle before job `finally`; always `maybeNotifyIdle` after stale release; never drop `pendingNetworkRestart` on force-reset.

## Part B — Legado App functional findings (same thread)

These came up while live-repairing sources against the phone. They are **App product / engine** notes, not only PC script gaps.

### B1. MCP product surface

| Finding | Why it matters | Status |
|---------|----------------|--------|
